# AI学習ダッシュボードの作成

学習スクリプトはあるが、進捗が**ターミナルの流れる文字でしか分からない**状態を解消する。
GUIから開始/停止でき、世代ごとの指標がグラフで残り、Colabとローカルで同じデータを見られるようにする。

## このスキルの範囲

**扱う（ゲームが変わっても同じ）**

- 学習プロセスの起動・停止・監視をするGUI（Flask + SSE）
- 世代ごとの指標の記録・グラフ化
- Colab ⇄ ローカルのデータ連携（Google Drive）
- デスクトップアプリとしての起動
- 学習スクリプトが満たすべき**取り決め（contract）**

**扱わない（ゲームごとに全く違う）**

- 何をどう学習させるか（環境・報酬・ネットワーク構造・行動空間）
- ゲームのルール実装

この境界が重要。学習の中身までスキルに入れると、別のゲームでは**間違った前提**になる。

## 想定する使いどころ

**主な場面: ゲーム本体ができて、これからAIを作り始めるとき。**

```
ゲームの枠組みが完成
   ↓
「このゲームのAIを作って」  ← ここでこのスキルが起動する
   ↓
学習スクリプトを普通に設計・実装する
   （ただし §1 の取り決めを最初から満たす形で書く）
   ↓
ダッシュボードをテンプレートから組む
```

**学習スクリプトは「スキルに合わせて」書くのではない。**
ゲームに合った設計を普通に行い、**出力の形だけ**取り決めに沿わせる。
取り決めはJSONログ1つと標準出力1行だけなので、学習ロジックの自由度は一切下がらない。
後から直すより、最初からその形で書くほうが圧倒的に楽（`\r` の書き換えなど手戻りが消える）。

**もう一つの場面: 既に学習スクリプトがある場合。**
その場合は §1 でズレを洗い出して直してから、§3 以降へ進む。

## 手順

### 1. 学習スクリプト側の取り決めを決める（最初にやる）

`references/trainer-contract.md` を読む。学習スクリプト側で必要なのは2つだけ。

| 必要なもの | 用途 |
|---|---|
| 世代ごとに追記される**JSONログ** | グラフ・表の正となるデータ。プロセスが死んでも残る |
| 進捗を伝える**標準出力の1行** | JSONに書かれる前のライブ表示 |

**これから学習スクリプトを書く場合**は、この2つを最初から組み込む。合計20行程度で、
学習ロジックには影響しない。

**既にある場合**は次を確認する（ほぼ確実にズレている）:

- 進捗表示が `\r`（改行なし）になっていないか → **GUIには永久に届かない**。最頻の不具合
- 例外を握りつぶして終了コード0で終わっていないか → 失敗を成功と誤認する
- JSONログを書いているか。無ければ追加する

### 2. 記録する指標を決める

`references/metrics.md` を読む。**汎用の指標**（loss・学習速度・評価勝率など）はどのゲームでも同じ名前で記録し、
**ゲーム固有の指標**は別に足す。汎用部分を揃えておくと、ダッシュボード側をゲームごとに書き換えずに済む。

ゲーム固有の指標は勝手に決めず、**そのゲームで「強くなった」と言える数値は何かをユーザーに聞く**。

### 3. テンプレートをコピーして動かす

`templates/` を丸ごとコピーし、`dashboard_server.py` 冒頭の**「■ プロジェクト設定」だけ**書き換える。
指標の一覧はここで定義すれば、画面もグラフも表も自動で追従する（フロントは触らなくてよい）。

```
コピー先/
  dashboard_server.py   ← 設定を書き換える
  launcher.py           ← <アプリ名> を置換
  web/
    index.html  app.js  app.css  chart.js  icon.svg
```

GUIは**ディスク上のJSONを正**とし、標準出力のパースは「まだJSONに書かれていない
進行中の分」を補うだけに使う。この二段構えが要。テンプレートは既にそうなっている。

### 4. ゲームに合わせて画面を足す

基本形（進捗・グラフの2タブ）はテンプレートに入っている。必要なものだけ足す。

| タブ | 中身 | テンプレート |
|---|---|---|
| 進捗 | 現在値のタイル＋世代の一覧表 | ✅ 込み |
| グラフ | 指標の推移 | ✅ 込み |
| （AI思考） | LLMに改善を任せている場合のみ | 追加で作る |
| （集団） | 遺伝的アルゴリズム等で個体群がある場合のみ | 追加で作る |
| （対局ビューア） | 棋譜・リプレイを見せる場合のみ | 追加で作る |

**グラフを描く前に必ず `dataviz` スキルを読む。** 特に**2軸グラフは禁止**（単位の違う指標は別グラフにする）。
系列が多いときは色を増やさず、小さなグラフを並べる（small multiples）。

### 5. 起動方法とColab連携

- デスクトップアプリ化は `references/desktop-app.md`
- Colab連携は `references/colab-sync.md`

### 6. 最後に落とし穴チェック

`references/pitfalls.md` の一覧と照合する。**すべて実際に起きた不具合**で、
どれも「静かに壊れて気づけない」種類のもの。

## 検証

作った直後は必ず、**実際に1世代だけ学習を回して**通しで確認する。

```bash
# GUIと同じ経路（パイプ）で学習を起動し、進捗行が届くか見る
python -c "import subprocess,sys; p=subprocess.Popen([sys.executable,'train.py'],stdout=subprocess.PIPE,text=True); [print(repr(l)) for l in p.stdout]"
```

`\r` で書かれていると、ここで**1行も出ないまま世代終了まで待たされる**ので一発で分かる。
