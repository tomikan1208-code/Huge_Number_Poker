# 巨大数ポーカー（Huge Number Poker）

ポーカーの駆け引きと、配られたカードから数式を組んで**できるだけ大きい数**を作るパズルを
融合させたゲーム。答えは**自分で計算して入力**し、システムの計算値と一致しなければ失格になる。

7枚配られ、括弧を除いて5枚以下で数式を組む。`2` と `3` を並べて `23` にはできない。

---

```bash
npm install
npm start
```

→ http://localhost:3000

Windows なら `start.bat` をダブルクリックでも同じ（ポート掃除→依存確認→起動→ブラウザ）。

## CPU（AI）について

CPU は **人間と同じように計算を間違える**。前提は暗算ではなく**紙とペンでの手計算**。

難しさは「答えの大きさ」ではなく**計算過程**で決まる。
たとえば `(4+6)^9 = 10^9` は `6^9 = 10077696` より値は大きいが、
前者は「1 のあとに 0 を 9 個」書くだけ、後者は 36→216→1296→… と
多桁の乗算を繰り返す必要がある。所要時間が3倍違う。

さらに**計算に使える時間はポットのチップ数**で決まる。
手計算なので、時間が余れば**見直せる**。つまりベット額がそのまま正答率になる。

`6^9` を上級CPU（大学生）が解いたときの正答率:

| 30秒 | 60秒 | 120秒 | 300秒 |
|---|---|---|---|
| 1% | 23% | 82% | 91% |

同じCPUでも `(4+6)^9` なら30秒で 69%、60秒で 98%。所要時間が 69秒 対 25秒 と違うため。
**「大きい数を作る」より「その時間で書き切れる数を選ぶ」ほうが効く**のがこのゲーム。
CPU はそれも織り込んでベット額と式を決める。

ベット額は3つの釣り合いで決まる ——
**計算時間**（賭けると時間が伸びて自分の正答率が上がる）、
**フォールドエクイティ**（大きく賭けるほど相手は降りる。ブラフが成立するのはここ）、
**トーナメントの価値**（全部失えばそこで終わり。ICM で測る）。
ただしこのゲームの計算時間は**卓で共通**なので、大きなブラフは受けた相手の
正答率も上げてしまう。普通のポーカーには無いブラフのコストになっている。

**相手の読み**は学習した方策だけが持てる。観測に「何人がレイズ／オールインしたか」
「直前の仕掛けの大きさ」「自分より短いスタックの相手が何割いるか」などを入れてある。
学習していないときのヒューリスティックは相手を見ておらず、
ブラフも「弱いときに一定確率で仕掛ける」であって
「相手が弱そうだから仕掛ける」ではない。

強さは5段階（中学生 / 高校生 / 大学生・理系 / 競技者 / トップ競技者）。
筆算の速度・1操作あたりのミス率・検算で誤りに気づく確率・
知っている事実（九九、階乗、log表）が違う。

定数は**目標値に合わせて自動で当てたものではない**。手で決めて、決めた理由を
その定数のコメントに書いてある。根拠のあるもの（九九1回 ≈ 1秒、書字速度）と
判断で置いたものを混ぜないようにしている。

`node tools/calibrate-ai.js` は**要件の検査**（強い人ほど当てる／時間を足せば
当たる／`(4+6)^9` は `6^9` よりはっきり速い、など）と、**現在値の記録との差分**を出す。
差が出ること自体は失敗ではない。意図した変更なら `--snapshot` で記録を貼り替える。

## AI を試す（テストプレイ場）

http://localhost:3000/lab — ホーム画面の「🧪 AIテスト場」からも入れる。

**カードを並べて式を作り、計算時間（秒）と難易度を選ぶと、CPU の答えと正誤・正答率が出る。**
ゲームを回さなくても、狙った式の正答率をその場で確かめられる。

出るもの:

- システムの正解値と、要求される答え方（厳密値 / 桁数 / 規模）
- **理論正答率**（モデルの計算値）と**実測正答率**（実際に N 回解かせた結果）
- CPU の申告サンプル（何と答えて、当たったか外したか、どれくらい外したか）
- そうなる理由の内訳（所要時間・間に合う確率・作業記憶の超過・焦り係数…）
- 5段階を横並びにした比較表
- 計算時間 10〜600 秒のスイープ曲線（＝ベットを積むとどれだけ当たるようになるか）

もう1つのタブでは、手札7枚を渡して**1ハンドを最後まで回せる**。

```
① 交換前のベット → ② カード交換 → ③ 交換後のベット → ④ 候補と比較
```

相手も同じ AI が打つ。卓の状況は自分で決めてもいいし、
**「AIにまかせる」**にすればアンティとブラインドから全部AIが決める。

- 降りるか / いくら賭けるか。**選ばなかった額も全部**出る
  （出す額・そのときの計算時間・相手が降りる確率・選ぶ式・score）
- 降りた理由の書き分け（作れる式が弱い / オッズが合わない / 飛ぶリスクが勝つ）
- **降りても、続けていたら作る予定だった式とカード**
- 捨てる札と引いた札、交換で手が良くなったかどうか

モデルの定数（`COG`）を画面から書き換えて、その場で効き方を見ることもできる
（メモリ上だけ。良い値が見つかったら `js/ai-cognition.js` を直接直す）。

## AI を学習させる

方策（ベット・式の選び方・交換）を PPO で自己対戦学習する。
**正答率のモデルは学習しない**（人間を模した固定の物理法則として扱う。
学習させると「間違えないAI」に収束してゲームが成立しなくなる）。

### 何を目指して学習するか

**トーナメント**を戦う。1人を残して全員が飛ぶまでが1試合で、リバイ（買い直し）は無い。
目標は収支ではなく**勝ち残ること**。

チップの価値はトーナメントでは線形ではない（持っているほど追加1点の価値が下がるし、
飛んだら取り返せない）。そのため報酬は各ハンドの

```
ICM(ハンド後のスタック) − ICM(ハンド前のスタック)
```

にしている。ICM は「優勝確率はスタックに比例する」という仮定でスタックを順位期待値に
換算する標準的なモデル。この差分を全ハンド足すと、ちょうど最終順位の報酬に一致する
（potential-based reward shaping）ので、密な報酬を得ながら目標は順位のまま動かない。

主指標は**優勝率**（3人なら 0.333 が互角）と**平均順位**。
bb/hand も出してはいるが、短いスタックほど強制的に大きな勝負をさせられる分だけ
生存バイアスが乗るので、単独では読まない。詳細は `PROJECT.md` §13.3〜§13.4。

`models/policy_skilled.json` は40世代学習させた重み（観測85次元・ICM報酬）。
3人卓でランダム相手に優勝率 0.72（互角は 0.333）、平均順位 1.51（互角は 2.0）。
1試合の長さが 5.0 → 22.9 ハンドに伸びており、早々に突っ込んで飛ぶのをやめている。

### GUI で回す（Windows）

**`AI学習コントロールパネル.vbs` をダブルクリック。** それだけ。

コンソールもアドレスバーも出ず、独立したウィンドウで開く。
右クリック →「ショートカットの作成」でデスクトップに置けば普通のアプリになる。

開始／停止、レベルの切り替え、世代ごとのグラフと表、生ログがひととおり入っている。
ウィンドウを閉じるとサーバーも止まる（学習中なら停止と同じ扱い。
世代ごとに保存しているので、失うのは進行中の1世代分だけ）。

**起動しないときは `AI学習コントロールパネル.bat`** を実行する。
Python と依存パッケージを確認して、足りなければその場で入れられる。

初回だけ準備が要る:

```bash
pip install -r train/requirements.txt
```

Node.js も必要（環境＝ゲームのルールが Node 側にあるため）。

### 直接回す

```bash
python train/launcher.py    # GUI（Windows以外はこちら）
python train/train.py       # GUIなし
```

環境（ゲームのルールと巨大数エンジン）は **Node 側**が持ち、Python は学習だけを行う。
巨大数エンジンを Python に書き直すとルールが二重管理になるため、
`js/engine.js` を唯一の正としたまま stdin/stdout の NDJSON で繋いでいる。

環境変数で設定を渡す:

| 変数 | 意味 | 既定 |
|---|---|---|
| `HNP_MAX_GENS` | 何世代回すか | 30 |
| `HNP_NUM_ENVS` | 並列する卓の数 | 自動 |
| `HNP_DECISIONS` | 1世代で集める意思決定の数 | 8192 |
| `HNP_LEVEL` | 相手にする「人間」の計算力 | skilled |

環境だけの動作確認:

```bash
node train/env_server.js --selfplay 300 --level skilled
```

学習した重みは `models/policy_<レベル>.json` に出る。
ゲーム側が自動で読み、そのレベルの CPU が学習済みの打ち方をする
（無ければヒューリスティック方策で動くので、学習しなくても遊べる）。
