# 何を記録するか

**ゲームが変わっても意味が変わらない指標**と、**そのゲームでしか意味を持たない指標**を分ける。
前者を同じ名前で揃えておくと、ダッシュボード側をゲームごとに書き換えずに済む。

## 汎用（どのゲームでも同じ名前で記録する）

### 学習が進んでいるか

| キー | 意味 | 見方 |
|---|---|---|
| `loss` | 損失 | 下がればよいとは限らない。方策が変われば上がる |
| `kl` | 更新前後の方策のずれ | 急上昇は学習の暴走。0付近が続くのは学習停止 |
| `entropy` | 行動選択の乱雑さ | 下がりすぎ＝探索をやめた（局所解のサイン） |

**`loss` だけを見て良し悪しを判断しない。** 強化学習では損失は性能の指標にならない。

### 本当に強くなったか（最重要）

| キー | 意味 |
|---|---|
| `win_vs_random` | ランダム相手の勝率。**下限の確認用**。早期に頭打ちになる |
| `win_vs_best` | 過去最強の自分との勝率。**これが本命**。50%付近＝拮抗、55%超で更新 |
| `elo` | レーティング（対戦相手が複数いる場合） |

自己対戦は「自分だけ強くなったつもり」に陥る。**固定の基準（ランダム・過去の自分）との対戦**を
定期的に挟まないと、強くなったかどうか誰にも分からない。10世代ごと程度でよい。

勝率は必ず **0〜1** で記録する（表示時に100倍する）。

### 速度・規模

| キー | 意味 |
|---|---|
| `fps` | 1秒あたりの処理ステップ数。設定変更の影響を測るのに使う |
| `seconds_per_gen` | 1世代の所要秒数。残り時間の見積もりに使う |
| `games_finished` / `num_envs` | 完了した対局数／並列数 |

### ゲームが成立しているか

| キー | 意味 |
|---|---|
| `finish_rate` | 制限ステップ内に決着した割合。**低いと学習データが壊れる** |
| `avg_turn` / `best_turn` | 平均・最短の決着ターン数 |

`finish_rate` は見落とされやすいが重要。決着しない対局ばかりだと報酬が入らず、
何を学んでいるのか分からなくなる。

## ゲーム固有（毎回ユーザーに聞く）

**勝手に決めない。** そのゲームで「強くなった」「良い手を打った」と言える数値を確認する。

| ゲーム | 固有の指標の例 |
|---|---|
| カードゲーム | 平均獲得資源、デッキ別勝率、コンボ成立率、平均コスト |
| オセロ・囲碁 | 最終石差、序中終盤ごとの精度、角の獲得率、着手可能数 |
| 対戦格闘・アクション | 平均ダメージ効率、被弾率、コンボ継続数 |

### 「名前 → 数値」の集まりを記録する

デッキ別勝率のように、**項目数が実行時に決まる**指標は入れ子の辞書で持つ。

```json
{"episode": 42, "loss": 0.02,
 "deck_win_rates": {"abyss_deck": 0.53, "tech_deck": 0.61}}
```

ダッシュボード側は名前を**初出順**で固定して並べる。
その時点の成績順に並べ替えると、世代が進むたびグラフの並びが入れ替わって読めなくなる。

## 記録してはいけないもの

- **1世代に何百行も出るような細かい値** — ログが膨らみ、重要な行が押し流される。
  ステップ単位の進捗は標準出力で流し、JSONには残さない
- **導出できる値** — `win_rate` があれば `win_count` は不要。二重に持つとズレる
