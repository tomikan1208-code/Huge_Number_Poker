# 落とし穴チェックリスト

**すべて実際に起きた不具合。** 共通するのは「静かに壊れて、動いているように見える」こと。
ダッシュボードを作り終えたら、この一覧と照合する。

## 学習スクリプト側

**❌ 進捗を `\r` で出している**
パイプで読むGUIには**世代が終わるまで1文字も届かない**。「リアルタイム表示が動かない」の
原因はほぼこれ。`sys.stdout.isatty()` で出し分ける。

**❌ 例外を握りつぶして終了コード0**
呼び出し側が失敗を成功と誤認する。実例: LLMの自動改善ループが、学習がクラッシュしているのに
「指標に変化なし」と判定し続け、**188回空回りした**。原因に辿り着くまで誰も気づかなかった。

**❌ 進捗の刻みがステップ数ベース**
25ステップ刻みで最大120ステップだと `100/120` で止まって見える。**時間ベース**にし、
最終ステップは必ず出す。

**❌ JSONを `encoding` 指定なしで読み書き**
Windowsでは cp932 になり、日本語ラベルが入った瞬間に落ちる。
`encoding="utf-8"` と `ensure_ascii=False` を必ず付ける。

**❌ 学習ログを永続フォルダに保存していない**
Colabではランタイム切断のたびに消える。**グラフのデータが毎回失われる。**
チェックポイント(.pth)だけ保存していて、ログを忘れているパターンが多い。

## 設定を自動で書き換える仕組みを持つ場合

**❌ 整数のパラメータを float で書き戻す**
`PPO_EPOCHS = 6.0` になると `range()` が `TypeError` で落ちる。しかも「元に戻す」処理が
その float を書き戻すため、**一度壊れると永久に直らない**。

対策は3つとも入れる:

1. 書き込み時に宣言型へ強制（`int` 指定なら `int()`）
2. **元の値を退避する時点でも**型を強制（これを忘れると revert が壊れ続ける）
3. 書き換えた直後に `ast.parse` で構文検証＋型検証し、不正なら**元のファイルに差し戻す**

**❌ 失敗しても延々と繰り返す**
連続失敗の上限（3回程度）を設けて停止する。
また「クラッシュしたか」だけでなく「**世代が実際に進んだか**」も確認する。
終了コード0で世代が進まない、という組み合わせが実際に起きる。

**❌ 失敗をLLMに伝えていない**
「指標が変わらない」としか見えないと、LLMは同じ提案を繰り返す。
学習が失敗した事実をプロンプトに明示する。

## ダッシュボード側

**❌ SSEの更新判定にログ件数を使う**
件数に上限があると、上限到達後は数値が変わらず**更新が止まる**。
判定には進捗の値そのものを含める。

**❌ ステータス更新のたびに全行を描き直す**
数千行の表を毎秒作り直すと重い。表はデータが変わったときだけ描き直す。

**❌ 2軸グラフ（左右で別スケール）**
目盛りの対応が恣意的で、実在しない相関を見せる。**単位が違う指標は別のグラフにする。**
グラフを作る前に `dataviz` スキルを読む。

**❌ 系列が増えたぶんだけ色を足す**
モノクロ配色なら特に、3系列以上は見分けられない。**小さなグラフを並べる**（small multiples）。
並び順は初出順で固定する（成績順にすると毎世代並びが入れ替わる）。

**❌ ツールチップでしか値を読めない**
数値を一覧できる表を必ず用意する。

## Windows / 起動まわり

**❌ 空きポート判定に `SO_REUSEADDR` を付ける**
Windowsでは**使用中のポートにも bind できてしまう**（Linuxと逆）。
既に別のサーバーがいるポートを「空き」と誤判定し、二重起動する。付けないこと。

**❌ `.vbs` をUTF-8で保存**
Windows Script Host はANSIとして読むため、日本語コメントが化けて**次の行のコードを巻き込む**。
エラーも出ずに何も起動しない。**UTF-16LE(BOM付き)**で保存する。

**❌ `pythonw.exe` で `print()` する**
コンソールが無い環境では `sys.stdout` が `None` になり得て、`print()` が例外で即死する。
しかも画面に何も出ない。起動時にログファイルへ逃がす。

**❌ `taskkill /IM python.exe` で終了させる**
他のPythonプロセスを巻き込む。**ポート番号から対象PIDを特定**して止める。

## exe化する場合

**❌ `sys.executable` で子プロセスを起動**
凍結後は exe 自身を指すため、学習の代わりにGUIが再起動する。
`getattr(sys, 'frozen', False)` で分岐し、実機のPythonを探す。
